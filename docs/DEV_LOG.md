## 1. Goal

Let 8 human players play at once. The game supports a maximum of 6. The user has 2 multitaps. The player-select UI must also let 8 players be chosen.

- Final deliverable: a patched `SLUS_207.87` repacked into a bootable ISO that runs on a real PS2 as well as on PCSX2 (preserve file order and LBAs; dual-layer DVD).
- Workflow: prototype each change as a `.pnach` in PCSX2 (fast iteration, PINE, debugger). Once stable, translate each pnach line into a direct ELF patch (vaddr = fileoff - 0x80 + 0x100000) and rebuild the ISO. Real PS2 has no debugger, so everything must be validated in PCSX2 first.
- The user plays on PCSX2 on macOS (can only play on real hardware via the final ISO).

## 2. Environment

- macOS. Project folder: `<project folder>` (contains the extracted disc, the original ISO, `PACLIST.H`, `tools/`, and this file).
- PCSX2 v2.8.2 at `/Applications/PCSX2-v2.8.2.app`. Config: `~/Library/Application Support/PCSX2/`. Cheats folder: `.../PCSX2/cheats/` (the pnach is installed there as `9B85B093.pnach`).
- Settings that matter: `EnablePINE = true` (IPC at `$TMPDIR/pcsx2.sock`, a unix socket on macOS), `EnableCheats = true` (ticked in Settings > Emulation, it was off before), `EnablePatches = true`.
- Only stdlib Python3 available (no Ghidra or capstone). Run scripts from the `tools/` folder. Note: `python3 -I` drops the script directory from the path, so scripts that import `dis` or `pine` must be run without `-I` (or with `PYTHONPATH`). `dis.py` shadows the stdlib `dis` module.
- Keyboard controls in PCSX2 (Pad1): arrows = D-pad, `K` = Cross (select), `I` = Triangle (back), `L` = Circle, Return = Start. The game only registers keys held ~0.2-0.4 s; quick taps are missed. Driving PCSX2 from Claude: use `computer_batch` `hold_key` (background `app_key` taps are ignored). In list menus a 0.2 s hold = 1 step, 0.3-0.35 s = ~2 steps (key repeat); in the wrestler grid use 0.35 s. The emulator queues keys and the screen lags 1-3 s, so wait 3+ s before reading it. Click the game window BODY (not the title bar, that can minimize it) to focus it; the Claude app can steal focus mid-batch.
- PCSX2 behaviours worth knowing:
  - System > Reset can close the app. Use System > Shut Down Without Saving, then double-click the game in the list (the app resumes the last save state otherwise).
  - Tools > Reload Cheats/Patches applies pnach changes without a reboot (patch=1 lines re-apply continuously, so writes made via PINE to patched addresses get overwritten within a frame).
  - Debugger: Debug > Open Debugger. Breakpoints: Breakpoints tab, right-click empty area > New (Memory, Read/Write, size). The Stack tab shows named frames because the ELF has symbols.
  - A frozen-looking "NOW LOADING" or PLAY screen with `FPS: N/A` means the game thread is stuck; see section 7.

## 3. PINE protocol (what worked)

- Packet: u32 total_len (including these 4 bytes) + payload. Reply: u32 len + 1 status byte (0 = ok) + data.
- Opcodes used: 0x00 read8, 0x02 read32, 0x03 read64, 0x04 write8, 0x05 write32, 0x0B title, 0x0F status (0 running, 1 paused, 2 shut down / no VM).
- Batching many read64 commands (5 bytes each) in one packet dumps all RAM 0x100000-0x2000000 in about a second (`tools/dump.py out.bin`).
- `tools/pine.py` has read32 / write32 / read8 / write8 / status / title helpers.

## 4. THE BIG DISCOVERY: the ELF has a full symbol table

An early note said "no symbols"; that was wrong. Section headers are at file offset 5652564: `.symtab` (0x5F9B0 bytes, 24,475 symbols) and `.strtab`. Heap section starts at 0x5A1000.

- `tools/symbols.txt` (addr, size, type, mangled C++ name) is generated by `tools/syms.py`. Type 2 = function, type 1 = object.
- Always `grep` it first. PCSX2's debugger Stack tab shows these names too.
- Useful names: `ExshibitionMenuSequence::{PlayerEntry,PositionSelect,WrestlerSelect,ArenaSelect}Next/End` (0x131D80-0x132370), `PositionSelectFrame` (0x1394F0+), `InitPositionInfo` (0x1307B0), `GetMatchWrestlerNo` (0x12CCE0), `CMatchMakeSystem` (0x30AA80-0x310560: `MatchCast` 0x30BB30, `MatchMake` 0x30B2F0, `SetResultData` 0x30CE00), `CChar::CChar` (0x1B9C40), `CreateGameChar` (0x1FB150), `GameLoad_Char` (0x1FD940, `LoadEnd` 0x1FD9E0), `MakeGameLoad_Char` (0x1FDE20), `StartCharSetup` (0x1FA0B0), `GameMem::Setup` (0x1FEED0), `CFile::*` (0x146D80-0x1482F0), `MakeCharName` (0x201AE0), `tblPosSelectLayout` (data, 0x45BD10).

## 6. What was found and done (chronological, with addresses)

### 6.1 False leads (do not repeat)
- `0x529f90` (1,2,3 across match sizes): a cursor into a shuffled table.
- `0x4920E2` / `0x4922C6`: 16-bit values 2/4/6 are the "player count" byte (+34) of a 44-byte rule struct (`tagRule`) at `0x4920C0`, copied from the default rule table, not a global total. The bit-7 mask loop at `0x181D0C` is `GetGardOffRule`.
- The 12-slot pool at `0x528FA0` (vtable `CModelAud2`, creator `MakeModelMot(C3DAudience*,CStage*)`) is the AUDIENCE, not wrestlers.
- `0x42E674` (looked like a cursor): audio thread.
- `0x2139E0` loop (`slti s1,6`) and the +472/+524/+548 arrays: this is `C3DAudience::C3DAudience` (0x213650), audience models, NOT wrestlers. Do not patch it.

### 6.2 Match rules table (done, prototype)
- Table `0x46CF60`: 86 match types, 24 bytes each: team byte per slot at +16..21, player count at +22; accessor `0x336B70` (29 callers; ~24 read the count byte at +22).
- The entry has no room for slots 6 and 7. Solution (prototype): relocate to RAM at `0x01F00000` with stride 32 (slots 0-7 teams at +16..23, count at +24), rewrite the accessor at `0x336B70` (4 instructions), and change 24 `lb x,22(v0)` count readers to offset 24. Loop caps `0x312BA8`, `0x338578`, `0x257BC8` go 6 to 8. Slots 6 and 7 get teams 0 and 1 (4v4).
- `0x01F00000` is an unverified guess at free RAM; the real ELF patch needs a proper cave (all zero runs inside the ELF turned out to be runtime buffers; BSS is fully used; heap starts 0x5A1000).
- With counts set to 8 the match types worked in menus but the setup logic was mismatched, so the stable pnach keeps counts at 6 (`KEEP6=1`).

### 6.3 Player-count menu: "7 PLAYERS" / "8 PLAYERS" (done, works)
- String table: pointers at `0x40DF70`, 830 ids, getter `0x12FD60` (bounds check `slti ...,830` at `0x12FD70`).
- "1 PLAYER".."6 PLAYERS", "ALL COM" are ids 69-75. The pnach copies the pointer table to `0x01F02000` with 834 entries (ids 830/831 keep the old "not found" behaviour; 832/833 = new strings at `0x01F03000`/`0x01F03010`), patches `0x12FD70` (bound 834), `0x12FD78` (`lui v0,0x1F0`), `0x12FDA0` (`addiu v0,v0,0x2000`).
- Menu builder `0x131D80` uses config records at `0x45AF60` (32 B each, +1 = max players; record 8 = Normal 6-man, 9 = Tornado 6-man) and a pointer table of zero-terminated id lists at `0x40EE00`. The pnach sets max players to 8 for records 8 and 9 (`0x45B061`, `0x45B081`), adds lists at `0x01F01000`/`0x01F01040`, and points `0x40EE14`/`0x40EE18` at them.
- Pad scan loop `0x131E48` changed 6 to 8. The game already has 8 pad objects (stride 192) at `0x4FEE00`.
- The menu shows 1-8 PLAYERS; options are only enabled up to the number of connected pads (set Controller Port 1 and 2 as multitaps in PCSX2 to get 8).
- Selecting 7 or 8 leads to an unsupported match (see 7).

### 6.4 Position screen (not done)
- Constructor `PositionSelectFrame` `0x139CC0`; loops 6 buttons (`slti s0,6` at `0x139DAC`), then a Continue button. Layout table `tblPosSelectLayout` at `0x45BD10`: per layout 7 entries x 28 bytes (6 boxes + Continue), floats x = 142 / 498, y = 190 / 244 / 296. Button pointers live at screen-object +360..383, Continue at +384, cursor at +388; many other structs use offsets 548+, so layout shifts are risky.
- Labels "1P".."6P" are string ids 96-101. Dialog "The position has not been decided yet" is dialog index 51 of the table at `0x45E420`.
- Adding 7P/8P needs a 4th row in each column (layout squeeze) plus the Continue check.

### 6.5 Characters (`g_pChar`) and the no-referee finding
- Wrestlers are `CChar` objects (vtable `0x47DAB0`, kind at +464) in the global array `g_pChar` at `0x526EA0` (8 pointers). In a 6-man match slots 0-5 are wrestlers, slot 6 is the referee, slot 7 is empty. About 476 instruction pairs reference `g_pChar`.
- Rule table `0x455DC0`, 64 bytes per rule (`GetDefRule` `0x12CC90`): byte +33 = referee flag (`IsRefereeRule` `0x33BDF0`), byte +34 = player count. Rule 9 = Tornado 6-Man Tag. `IsThereReferee` (`0x1C4930`) scans g_pChar for kind 1; callers `SetDq`, `SetKO`, `SetGIV`, `CCharExDrop`. Only 5 of 86 rules have the flag off (ids 58, 59, 60, 80, 82).
- Test: `patch=1,EE,00456021,byte,00` removes the referee for rule 9. Result: g_pChar had only the 6 wrestlers (slots 6, 7 null) and an AI match still ended with a winner (pin or finish worked; a referee model still appeared in the post-match cutscene). Count-outs, DQ, submissions not tested. This idea fits 8 wrestlers exactly into the 8-entry g_pChar (no relocation needed).

### 6.6 Wrestler creation path
- Slot records at `0x4921C0 + 32*i` (i < 8): +4 kind, +8 active byte, +9 team, +10 hword model id (25500 = none; >= 10000 edit wrestler). Rebuilt from a table at `0x529430` (stride 32) by the match setup loop at `0x258020-0x2582B0` (`slti v0,s4,8`).
- `MakeGameLoad_Char` (`0x1FDE20`) loop `slti s1,7` at `0x1FDF4C` (slots 0-6). `GameLoad_Char` ctor (`0x1FD940`) turns the model id into a filename (`MakeCharName`: id < 3000 gives `/EMD/%d`, else `/EMD2/%d`) and queues a `CFile::NBRead`. `LoadEnd` calls `CreateGameChar` which fills `g_pChar[idx]`. `StartCharSetup` (`0x1FA0B0`) loops 8 slots.
- Model id = roster id * 100 (+1 for some variants, depending on which file exists, e.g. `/EMD/601`, `/EMD/801`, `/EMD/301`, `/EMD/501`, `/EMD/101`). Roster table (runtime) at `0x4C1068`, stride 368, `GetMatchWrestlerNo` `0x12CCE0`. In a test match the slot ids were 0 (Rock), 4400 (Brock), 200, 100, 300, 500.
- `CMatchMakeSystem::MatchCast` (`0x30BB30`) etc. own about 80 hard-coded 5/6/7 limits in `0x309000-0x316000`; the setup builder at `0x30C4F0-0x30C700` uses 208-byte elements with 6 entries of 32 bytes.

- 2026-10-27 survey: `CMatchMakeSystem` callers are `CSeasonSystem::nvMatchMake/nvGameInit/nvGameEnd` (0x256DF0-0x2587C0), so the season engine also runs exhibition. ~110 literal 5/6/7/8 compares in 0x309000-0x316000, but many belong to unrelated code (shop UI `CsnShop*`, `RankingSort`, `GetStableMemberList`). Real match-setup candidates: `MatchMake` 0x30B2F0, `MatchCast` 0x30BB30, `SetResultData` 0x30CE00, `SetRoyalRumble` 0x310560, `nvGameStart` 0x257EA0 (7 hits), `nvGameInit` 0x2579E0 (6 hits). Not yet patched or tested.

### 6.7 Memory budget wall (partly superseded: see 12.1 and 12.5; the stall was the 1 KB page for empty slots 6/7, and 16.8 MB of heap are actually free)
- Per-character memory pages are set by `GameMem::Setup` (`0x1FEED0`), table at `0x419D60` (KB sizes, zero-terminated; pages start at index 2: 1408, 2740/2820/3076, then 480 per slot, with 164 for the referee slot), applied with `ymemReallocatePage(2, table)` (`0x140C90`). Loop `slti v0,s3,7` at `0x1FF080`; empty-slot reserve check `slti at,s3,6` at `0x1FF00C`.
- With those patched to 8 and slots 6, 7 forced, loading proceeds further but PCSX2 then executes garbage and dies (memory corruption from other 6-sized structures).

### 13.7 Kernel RAM is overwritten at the crash (2026-10-27) and the likely cause
- PINE CAN read kernel RAM through kseg0 addresses (0x80000000+), not through 0x0+ (that earlier gave zeros, so 12.11 was wrong about not seeing it). Dump at the slot-7 crash: 0x80000000-0x80030000 (192 KB) is full of non-zero data that is not code (image/model-like bytes); only the first 0x1000 bytes still hold the exception vectors. `0x80000180` (general exception vector) reads 0x2F2F350A garbage. So a ~192 KB file read landed at address ~0x1000, i.e. a read into a NULL buffer.
- Likely path: `CFile::StartNextNBRead` does `Alloc(size*256, ...)`; if it returns 0 (page too small) the buffer stays NULL and the read goes to address 0. The per-slot page size is chosen in `GameMem::Setup` (0x1FEED0) from the model id AT SETUP TIME: 0x1E0 (480 KB) when id%10==0, 0x290 (656 KB) otherwise, 0x350 (848 KB) when id%10==3. Forced slots 6/7 (ids 601, 801, %10 == 1) get only 480 KB (empty-slot reserve) -> too small -> NULL alloc -> kernel overwritten. It fits the earlier observation that 480/164 KB experiments crashed the same way.
- Test: `tools/exp_s7p.pnach.txt` = exp_s7 + empty-slot reserve at 0x1FF018 raised to 848 KB (`24120350`). Not yet run. Real fix for the ELF: make `GameMem::Setup` size slots 6/7 from the real picks (or always 848 KB) and add a NULL check for the `Alloc` result in `StartNextNBRead`.
